# SnapHerb

SnapHerb คือโปรแกรมเดสก์ท็อปสำหรับ **เบิกยาสมุนไพร** จากยอดสั่งจ่ายที่บันทึกใน HOSxP
สร้างด้วย Tauri 2 + Leptos 0.8 โดยอ่านข้อมูล HOSxP แบบอ่านอย่างเดียวเท่านั้น

หน้าจอและใบเบิกจากระบบใช้ธีมเขียวของ `logo.svg` (กบถือแคปซูล)
ส่วนใบเบิกพัสดุ (ทางการ) คงรูปแบบเอกสารราชการขาวดำตามแบบฟอร์มของโรงพยาบาล
ผู้ใช้ตรวจใบเบิกบนหน้าจอ แล้วพิมพ์ออกทางเครื่องพิมพ์ **2 ฟอร์ม** ต่อกันในชุดเดียว

## ฟีเจอร์

- เชื่อมต่อ HOSxP (MySQL/MariaDB) พร้อมเก็บรหัสผ่านแบบเข้ารหัสใน OS keychain
- เข้าสู่ระบบด้วยบัญชี `officer` ของ HOSxP
- ตั้งค่าแพทย์ที่ต้องการตรวจจับการสั่งจ่าย จากตาราง `doctor` พร้อมค้นหาแบบอัตโนมัติเมื่อพิมพ์ 3 ตัวอักษรขึ้นไป
- ตั้งค่ายาสมุนไพรที่ต้องการตรวจจับ พร้อมค้นหาแบบอัตโนมัติเมื่อพิมพ์ 3 ตัวอักษรขึ้นไป และเพิ่มรายการที่ไม่มีใน HOSxP ด้วยตนเองได้
  - หน่วยนับการใช้ เช่น เม็ด
  - หน่วยเบิก เช่น กล่อง
  - จำนวนหน่วยนับใน 1 หน่วยเบิก เช่น 100 เม็ด/กล่อง
  - จำนวนสูงสุดที่เบิกได้ต่อรอบ เช่น 30 กล่อง
  - รายการที่เพิ่มเองจะไม่ถูกดึงยอดใช้จาก HOSxP แต่สามารถเพิ่มในใบเบิกพร้อมเหตุผลได้
- เลือกช่วงวันที่เบิกได้ถึง **วันที่ก่อนหน้าวันที่ปัจจุบัน** แล้วดึงยอดใช้จาก HOSxP ตามแพทย์ที่เลือก (ไม่จำกัดแผนก)
- คำนวณจำนวนเบิกเป็นหน่วยเบิกอัตโนมัติ
  - ใช้ 130 เม็ด, 1 กล่อง = 100 เม็ด → เบิก 1 กล่อง
  - ใช้ 150 เม็ด → เบิก 2 กล่อง
  - ใช้ 500 เม็ด → เบิก 5 กล่อง
  - ไม่เกินจำนวนสูงสุดที่ตั้งไว้
  - รายการที่คำนวณแล้วจำนวนเบิกเป็น 0 จะไม่แสดงในใบเบิก
- แก้ไขจำนวนเบิกหรือเพิ่มรายการที่ระบบไม่พบยอดใช้ได้ **โดยต้องระบุเหตุผล**
- เหตุผลการเพิ่ม/แก้ไขจะถูกพิมพ์ในใบเบิก
- ตั้งค่าผู้ลงนามในใบเบิก: ผู้รับ ผู้สั่งจ่าย ผู้จ่าย และหัวหน้างาน พร้อมตำแหน่ง
  (ชื่อผู้เบิกดึงจากบัญชีที่เข้าสู่ระบบ)
- พิมพ์ **2 ฟอร์ม**: ใบเบิกจากระบบเดิม และใบเบิกพัสดุ (ทางการ)
  - ใบเบิกทางการมี 4 ลายเซ็น: ผู้เบิก ผู้รับ ผู้สั่งจ่าย และผู้จ่าย
  - เลขที่ใบเบิกใช้เลขของโปรแกรม เช่น `SH-25691024-001`
  - แบบฟอร์มระบบเดิมเปลี่ยนช่องลงนามผู้จ่ายเป็น **หัวหน้างาน**
- เมื่อพิมพ์แล้ว ระบบจะบันทึกและล็อกช่วงวันที่นั้น **ถาวร** ไม่สามารถแก้ไขหรือเบิกซ้ำได้
- ดูประวัติและ **พิมพ์ซ้ำ** ใบเบิกที่บันทึกไว้ได้
- หน้าตาตาม `logo.svg`: โทนเขียว pastel, กบ, แคปซูล, การ์ดมน และตัวอักษรไทยที่อ่านง่าย

## การคำนวณจำนวนเบิก

```
จำนวนเบิก = round(จำนวนใช้ ÷ จำนวนหน่วยนับใน 1 หน่วยเบิก)
```

ใช้การปัดแบบครึ่งขึ้น (0.5 ขึ้นไปปัดขึ้น) แล้วจำกัดไม่ให้เกินจำนวนสูงสุดต่อรอบ

## การล็อกช่วงวันที่

- การกด **พิมพ์และล็อกช่วงวันที่** จะบันทึกใบเบิกและล็อกช่วงวันที่ทันที
- ช่วงวันที่ใดที่มีใบเบิกแล้ว จะไม่สามารถแก้ไขหรือเบิกซ้ำได้อีก
- หากเลือกช่วงวันที่ทับซ้อนกับใบเบิกเดิม ระบบจะแจ้งเลขที่ใบเบิกและหยุดทำงาน
- ใบเบิกเดิมยังเปิดดูและ **พิมพ์ซ้ำ** ได้จากหน้าประวัติ

ข้อมูลประวัติและสถานะล็อกเก็บไว้ในเครื่องนี้เท่านั้น ไม่ได้เขียนกลับไปที่ HOSxP
โปรแกรมเปิดได้ครั้งละหนึ่งหน้าต่างเพื่อป้องกันการเขียนไฟล์ประวัติซ้อนกัน

## การติดตั้งและรัน

ต้องมี Rust, `wasm32-unknown-unknown`, Trunk และ Tauri CLI

```bash
rustup target add wasm32-unknown-unknown
cargo install trunk --version 0.21.14 --locked
cargo install tauri-cli --locked

# รันแอป
cargo tauri dev
# หรือ
npm run tauri dev
```

ถ้าใช้ Tauri CLI เวอร์ชันอื่น ให้เลือกเวอร์ชันที่รองรับ Rust ของเครื่อง

สร้างชุดติดตั้ง:

```bash
cargo tauri build
```

ไฟล์ติดตั้งจะอยู่ใต้ `target/release/bundle`

## Windows release

มี GitHub Actions สำหรับสร้างชุดติดตั้ง Windows แล้ว:

- **ทดสอบสร้าง Windows installer แบบ manual**: ไปที่ `Actions` → `Test Build` → `Run workflow` แล้วดาวน์โหลด artifact ชื่อ `snapherb-windows-installers` (มีทั้ง `.msi` และ `.exe` จาก NSIS)
- **ออก release เต็มรูปแบบ**: สร้าง tag ให้ตรงกับเวอร์ชันใน `tauri.conf.json` แล้ว push
  ```bash
  git tag v1.26.1025
  git push origin v1.26.1025
  ```
  workflow `Publish Release` จะสร้าง GitHub Release พร้อมไฟล์ติดตั้ง Windows, Linux และ macOS

หมายเหตุ: Windows ต้องมี WebView2 Runtime (มีมากับ Windows 10/11 รุ่นที่อัปเดตแล้ว) และไฟล์ติดตั้งยังไม่ได้ลงลายเซ็น อาจพบหน้า SmartScreen

```
crates/models           ชนิดข้อมูล แพทย์ ยาสมุนไพร ช่วงวันที่ ใบเบิก และรูปแบบไทย/พ.ศ.
crates/core             ตรรกะคำนวณกล่อง รายงาน การแก้ไข เหตุผล การแบ่งหน้า และการล็อก
crates/hosxp-connector  ชั้นเดียวที่อ่าน MySQL ของ HOSxP (SELECT เท่านั้น)

app                     หน้า Leptos + CSS + ใบเบิก A4 ที่พิมพ์ได้
logo.svg                ต้นแบบแบรนด์สำหรับไอคอนและงานภาพ
```

## การเชื่อมต่อ HOSxP

แนะนำให้สร้างผู้ใช้ MySQL สำหรับ SnapHerb โดยให้สิทธิ์อ่านอย่างเดียว:

```sql
CREATE USER 'snapherb_ro'@'%' IDENTIFIED BY 'เปลี่ยนรหัสผ่าน';
GRANT SELECT ON hos.* TO 'snapherb_ro'@'%';
```

แอปจะรัน `SET SESSION TRANSACTION READ ONLY` ทุก connection และมี SQL guard
ป้องกันคำสั่งที่ไม่ใช่ `SELECT`/`WITH` อีกชั้น

รายละเอียดคิวรีและประเด็นที่ต้องยืนยันกับผู้ดูแลฐานข้อมูลอยู่ใน
[`docs/database.md`](docs/database.md)

## ไฟล์ที่เก็บในเครื่อง

อยู่ใต้ app config directory ของระบบปฏิบัติการ:

- `snapherb.config.json` – การตั้งค่าการเชื่อมต่อที่เข้ารหัสแล้ว
- `snapherb.settings.json` – แพทย์ ยาสมุนไพร ผู้ลงนาม และหัวใบเบิก
- `snapherb.requisitions.json` – ประวัติใบเบิก ช่วงวันที่ที่ล็อก และข้อมูลผู้ลงนามของใบเบิกนั้น

ไม่มีการเก็บข้อมูลผู้ป่วย เก็บเฉพาะรายการยา จำนวน และชื่อผู้เกี่ยวข้องในใบเบิกเท่านั้น

## การพิมพ์ 2 ฟอร์ม

เมื่อกดพิมพ์ ระบบจะพิมพ์เอกสารต่อกันเป็นชุดเดียว:

1. **ใบเบิกจากระบบ (แบบเดิม)** – ตารางยา จำนวนใช้ จำนวนเบิก และเหตุผลการแก้ไข
   พร้อมช่องลงนามผู้เบิกและ **หัวหน้างาน** (ชื่อหัวหน้างานตั้งค่าได้)
2. **ใบเบิกพัสดุ (ทางการ)** – ตามแบบฟอร์มใบเบิกพัสดุของโรงพยาบาล (ไฟล์ต้นฉบับเก็บไว้ในเครื่อง ไม่ได้อยู่ใน Git)
   มี 4 ลายเซ็น คือ ผู้เบิก ผู้รับ ผู้สั่งจ่าย และผู้จ่าย
   โดยผู้เบิกใช้ชื่อจากบัญชีที่เข้าสู่ระบบ และอีก 3 ท่านตั้งค่าได้ที่แท็บ **ผู้ลงนาม**

ใบเบิกทางการใช้เลขที่เดียวกับโปรแกรม เช่น `SH-25691024-001`
และรองรับการแบ่งหน้าละ 20 รายการ
